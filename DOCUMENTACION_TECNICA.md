# Watchlist+ (WatchlistPlus) - Documentación Técnica

## 📝 Descripción General
Watchlist+ es una extensión de navegador de alto rendimiento construida bajo el estándar Manifest V3 (compatible con Chromium 109+ y Firefox 109+) diseñada para resolver la fragmentación y el seguimiento manual en el consumo de series, anime y películas en la web. La solución detecta, cataloga y sincroniza de forma automática e instantánea el progreso de reproducción en cualquier reproductor o sitio web de streaming en tiempo real sin requerir interacción manual del usuario. Integra una arquitectura local-first con respaldo modular en la nube (Google Drive API), un asistente de inteligencia artificial conversacional y anti-spoilers (Google Gemini 3.8 Flash), un despachador de alertas de emisión semanal al móvil vía Telegram Bot API y gestión multi-perfil, todo desarrollado con cero dependencias externas en tiempo de ejecución (100% compliant con las normativas de la Chrome Web Store, Edge Add-ons y Opera Add-ons).

## 🛠️ Stack Tecnológico
* **Sistema Operativo Base:** Multiplataforma (Linux Debian 12 / Windows 11 / macOS como entornos de desarrollo, compilación y pruebas; navegadores basados en motores Chromium V8 y Gecko).
* **Lenguajes / Entornos:** JavaScript vanilla (ES6+ moderno, WebExtensions API, Service Worker Manifest V3, Content Scripts reactivos, DOM MutationObserver). Node.js (entorno de pruebas, empaquetado y verificación estricta de sintaxis). Google Apps Script (entorno serverless V8 en la nube para backend complementario y webhooks).
* **Base de Datos / Persistencia:**
  * *Local-First:* `chrome.storage.local` como motor de persistencia transaccional indexado por perfiles de usuario, con bus reactivo mediante `chrome.storage.onChanged` y caché de resúmenes.
  * *Sincronización en la Nube:* Google Drive REST API v3 (OAuth2 con alcance restringido `drive.appdata`), utilizando arquitectura multi-archivo por perfil (`profile_${id}.json`) coordinados por un índice maestro (`profiles_index.json`).
  * *Backend y Persistencia Relacional:* Google Sheets administrado por Google Apps Script (`backend/AppsScript_ProValidator.js`) con cerrojos de concurrencia atómicos (`LockService`) para las hojas `Usuarios_PRO`, `Telegram_Users`, `Telegram_Airings` y `Reportes_Webs`.
* **Componentes de IA / Automatización:**
  * *Google Gemini API REST v1beta:* Integración con modelos Gemini (Gemini 3.8 Flash, Gemini 2.5 Flash y Gemini 1.5 Flash) con arquitectura multi-modelo tolerante a fallos, autodescubrimiento dinámico de versiones, compresión semántica de catálogo (~90% de ahorro de tokens), rate limiting de 3s y persistencia en caché inmutable por capítulo.
  * *Motor Híbrido de Metadatos:* AniList GraphQL API (zero-tokens para anime en emisión, demografías canónicas y huso horario de estreno) + TVmaze REST API (series occidentales y temporadas) + Wikipedia / DuckDuckGo Instant Answer API (pósters teatrales cinematrográficos HD en proporción 2:3).
  * *Automatización y Mensajería Externa:* Telegram Bot API (`sendPhoto`, `sendMessage`) con disparadores cron diarios automáticos (Google Apps Script Time-driven triggers a las 09:00 AM) y soporte de códigos QR vectoriales generados nativamente en SVG (`qrGenerator.js`) sin CDNs ni librerías de terceros.

## 🔄 Flujo de Datos y Arquitectura
1. **Entrada de datos:**
   El script inyector de contenido (`content.js`) se inyecta en el contexto de navegación (`<all_urls>`). Monitoriza dinámicamente el ciclo de vida de la página interceptando eventos del historial (`history.pushState`, `history.replaceState`, `popstate`, `hashchange`) y mutaciones del DOM mediante un `MutationObserver` anclado a `document.documentElement` para garantizar compatibilidad con SPAs (React, Vue, Angular). Simultáneamente, la función `monitorVideoProgress` analiza los elementos `<video>` para detectar eventos de finalización (`ended` o progreso > 90%). Al detectarse actividad, envía un mensaje asincrónico (`notifyUrlChange` / `checkCurrentTab`) al Service Worker central.
2. **Procesamiento lógico e inferencia de rutas:**
   El Service Worker (`background.js`) procesa el payload recibido mediante los analizadores `urlParser.js` y `streamingPlatforms.js`. Aplica heurísticas de expresiones regulares y evalúa reglas dinámicas remotas (`rules.json`). Si la URL corresponde a un nuevo episodio de una serie registrada, el controlador `storage.js` normaliza la estructura del objeto (`sanitizeSeries`), actualiza el historial cronológico (`watch_history`) y marca de forma automática todos los episodios precedentes con el estado `"visto"`.
3. **Interacción con la IA y Servicios Externos:**
   * *Recomendaciones y Resúmenes:* Al solicitar recomendaciones ("¿Qué veo hoy?") o resúmenes de contexto ("¿En qué me quedé?"), `aiService.js` verifica primero la caché local inmutable. En caso de consulta nueva, genera un catálogo minificado y despacha una petición REST autenticada a la API de Google Gemini con control estricto de temperatura (0.3 factual para conteos y progreso / 0.75 creativo para recomendaciones con la identidad de la mascota Kuro-Byte; instrucción estricta de cero spoilers de capítulos posteriores).
   * *Catalogación Automática:* El botón `[ ✨ Auto ]` consulta en cascada la API GraphQL de AniList (para producciones de animación japonesa con 0 consumo de tokens) o Google Gemini (para cine y series occidentales), infiriendo automáticamente la categoría, demografía japonesa (Shounen, Seinen, etc.), géneros múltiples y horario de emisión semanal.
4. **Almacenamiento / Salida y Sincronización Reactiva:**
   Los cambios se persisten de forma atómica en `chrome.storage.local`. El sistema emite un bus de eventos en tiempo real (`SERIES_UPDATED` y `chrome.storage.onChanged`) que notifica a la interfaz de la biblioteca (`library.js`) y a la vista rápida (`popup.js`), refrescando el DOM en 0 ms sin recargar la página y preservando la posición exacta de scroll. En segundo plano, las alarmas programadas (`chrome.alarms`) coordinan el auto-respaldo modular hacia Google Drive (`driveSync.js`) y la sincronización de obras en emisión con la base de datos de Telegram.

## 🛡️ Consideraciones de Seguridad y Buenas Prácticas
* **Privacidad Absoluta (Arquitectura Local-First):**
  La totalidad de la información de la biblioteca, historial de visualizaciones, notas personales y perfiles se procesa y almacena localmente en el cliente (`chrome.storage.local`). Las peticiones a la IA no envían información identificable del usuario; la API Key de Gemini es de custodia exclusiva del usuario y se mantiene cifrada en el almacenamiento local.
* **Principio de Mínimo Privilegio (Manifest V3):**
  La extensión se apega estrictamente a las especificaciones de seguridad de Manifest V3. No se utiliza `eval()`, código remoto ejecutable ni dependencias de CDNs externas. Los permisos de red (`host_permissions`) están restringidos estrictamente a los endpoints indispensables de las APIs declaradas (`generativelanguage.googleapis.com`, `graphql.anilist.co`, `api.tvmaze.com`, `script.googleusercontent.com`).
* **Aislamiento de Alcance OAuth2 (Google Drive `drive.appdata`):**
  La autenticación en la nube utiliza el scope mínimo restrictivo `https://www.googleapis.com/auth/drive.appdata`. La extensión tiene acceso exclusivamente a su propia carpeta privada de aplicación en Google Drive, quedando estrictamente imposibilitada de leer, alterar o acceder a los archivos personales o documentos que el usuario almacene en su nube.
* **Control de Concurrencia y Transacciones Seguras:**
  En el backend de Google Apps Script se implementó `LockService.getScriptLock()` con bloqueo exclusivo de hasta 10 segundos para garantizar que webhooks simultáneos de compras o registros de Telegram no generen condiciones de carrera en Google Sheets. En el frontend, se emplean variables de exclusión mutua / semáforos asíncronos (`isLoadSeriesRunning`, `activeLoadSeriesPromise`) para prevenir desincronizaciones en ráfagas de eventos `storage.onChanged`.
* **Aislamiento Estricto por Perfil:**
  Cada perfil de usuario cuenta con su propio almacén de claves, su propio `chat_id` individual de Telegram y sus propios archivos de respaldo en Google Drive (`profile_${id}.json`), impidiendo cualquier colisión o contaminación cruzada de datos entre perfiles o dispositivos vinculados a la misma cuenta.

## 🚀 Desafíos Técnicos y Resoluciones (Troubleshooting)
* **Desafío:** Condiciones de Carrera y Duplicación de Tarjetas en el DOM (Race Conditions).
  * **Resolución:** Implementación de un candado de concurrencia (Mutex asíncrono) mediante las variables `isLoadSeriesRunning`, `hasPendingLoadSeries` y la retención de la promesa activa `activeLoadSeriesPromise`. Si una recarga está en ejecución, las subsiguientes se encolan atómicamente; además, se introdujo una ventana de debounce y persistencia milimétrica de scroll (`scrollTop` y `window.scrollY`).
* **Desafío:** Caducidad y Renovación Silenciosa de Tokens OAuth2 en Google Drive.
  * **Resolución:** Se implementó la detección proactiva de expiración mediante el cálculo de `drive_token_expires_at`. En `ensureValidToken()`, si restan menos de 60 segundos, se renueva preventivamente. Si la renovación silenciosa falla en tiempo de ejecución, escala transparentemente a reautenticación interactiva asistida con el parámetro `login_hint` (email del usuario) y `prompt=select_account`, resolviendo la aprobación en milisegundos sin solicitar credenciales nuevamente y permitiendo conmutar entre cuentas de Google en equipos compartidos.
* **Desafío:** Detección Universal en Aplicaciones de Página Única (SPAs) y HashRouters.
  * **Resolución:** En `content.js` se interceptaron los prototipos nativos de `history.pushState` y `history.replaceState`, combinados con escuchadores de `popstate` y `hashchange`. Para sobrevivir a la destrucción y reemplazo agresivo de nodos `<body>` en SPAs, el `MutationObserver` se ancló permanentemente al elemento raíz `document.documentElement`, garantizando la detección del episodio en 0 ms.
* **Desafío:** Optimización de Cuotas y Tolerancia a Fallos en Modelos LLM (Google Gemini).
  * **Resolución:** Se diseñó un formato de compresión minificado de catálogo (reduciendo ~90% los tokens de entrada al indexar solo campos clave como slug, género, demografía y estado). Se implementó almacenamiento en caché inmutable por capítulo (`gemini_recap_${serie}_${cap}`) a 0 tokens y 0 ms para resúmenes ya generados, rate-limiting con semáforo de 3s en la UI, y un mecanismo de cascada multi-modelo con autodescubrimiento dinámico de versiones (`gemini-3.8-flash`, `gemini-2.5-flash`, etc.) para garantizar alta disponibilidad.
